rankflex: Quick Tutorial

Shiyu Xiong, Ruowei Fang, Yang Li

Overview

rankflex provides a flexible framework for integrating, aggregating, and visualizing rankings from multiple sources. The built-in sample dataset (rankings_sample) covers global university rankings from QS, Times Higher Education (THE), and ARWU across 2023–2025, but every function works with any ranked domain — films, restaurants, sports teams, and so on.

The typical workflow is:

load_rankings()  ->  clean_rankings()  ->  merge_datasets()
      ->  standardized_scores()  ->  compute_composite()
      ->  compare_rankings() / sensitivity_analysis() / optimize_weights()
      ->  plot_ranking_static() / plot_ranking_dynamic()

1. The built-in dataset

rankings_sample is a long-format data frame: each row is one university × one source × one year.
Indicator columns belonging to other sources are NA for that row (e.g. score_teaching is only filled for THE rows).

2. Loading your own data

load_rankings() reads a CSV or Excel file and attaches source / year metadata columns automatically. load_data() is the full version with extra options (encoding, row-skipping, arbitrary metadata).

# Not run — replace with your own file paths
qs_raw   <- load_rankings("qs_2025.csv",            source = "QS",   year = 2025)
the_raw  <- load_rankings("THE_2016_to_2026.csv",   source = "THE",  year = 2025)
arwu_raw <- load_rankings("all_years_combined.csv", source = "ARWU", year = 2025)

3. Cleaning data

clean_data() (alias: clean_rankings()) auto-detects entity / rank / score columns, cleans text encoding, converts rank strings like "=1" or "101–150" to integers, and drops rows with missing ranks.

dirty <- data.frame(
  university_name = c(" Harvard University ", " Stanford University ", ""),
  ranking         = c("=1", "2", "3-5"),
  total_score     = c("98.5", "97.2", "90+"),
  stringsAsFactors = FALSE
)
cleaned <- clean_data(dirty, quiet = TRUE)
cleaned
#>                entity rank score
#> 1  Harvard University    1  98.5
#> 2 Stanford University    2  97.2

When starting from rankings_sample (already clean) you can skip this step.

4. Merging sources into wide format

merge_datasets() pivots a list of data frames into a wide table with separate rank/score columns per source (e.g. rank_QS, rank_THE, rank_ARWU).

Required columns: each data frame in the list must contain entity, year, source, rank, and score.
rankings_sample stores the overall score as score_overall, so we must create a score column first.

qs_long   <- rankings_sample[rankings_sample$source == "QS",   ]
the_long  <- rankings_sample[rankings_sample$source == "THE",  ]
arwu_long <- rankings_sample[rankings_sample$source == "ARWU", ]

qs_long$score   <- qs_long$score_overall
the_long$score  <- the_long$score_overall
arwu_long$score <- arwu_long$score_overall

final_wide <- merge_datasets(

5. Standardizing scores & computing a composite

Why filter to one source first?

rankings_sample is long format — the same university appears up to three times per year.
Each row only has indicator values for its own source; cross-source columns are NA. If you run standardized_scores() on the full dataset, most cells in the _std columns will be NA, and compute_composite() will return empty results.

Solution: filter to a single source before standardizing and computing.

qs_df <- rankings_sample[rankings_sample$source == "QS", ]
cat("QS rows:", nrow(qs_df), "\n")

qs_indicators <- get_indicators(qs_df)

  weights = weights,
  n_sim   = 100,
  top_n   = 15,

8. Optimizing weights for a target university

optimize_weights() uses linear programming (lpSolve) to find the weight vector that maximizes a given university’s composite score, subject to weights summing to 1 and no single weight exceeding max_weight.

# Which indicator set gives Peking University its best possible ranking?
opt <- optimize_weights(
  data       = qs_std,
  target     = "Peking University",
  indicators = chosen,
  year       = 2025,
  max_weight = 0.5,
  top_n      = 20
)

10. Animated ranking

plot_ranking_dynamic() creates a racing bar chart showing how rankings evolve over the three years. It requires gganimate and gifski.

# install.packages(c("gganimate", "gifski"))   # if not yet installed

gganimate::anim_save("university_ranking_race.gif", anim)

11. Using multiple sources together

If you want a composite that draws on indicators from QS, THE, and ARWU simultaneously, join the wide table back to the long-format data, or build a merged indicator matrix manually.

tri_source <- complete_2025[, c("entity", "year",
                                "rank_QS", "rank_THE", "rank_ARWU",
                                "score_QS", "score_THE", "score_ARWU")]

tri_std <- standardized_scores(
  tri_source,
  indicators = c("score_QS", "score_THE", "score_ARWU")
)

tri_weights <- c(score_QS = 1/3, score_THE = 1/3, score_ARWU = 1/3)
tri_composite <- compute_composite(tri_std, weights = tri_weights)

Quick-reference: column name rules

Situation What to pass
standardized_scores(df, indicators) original column names, e.g. "score_overall"
compute_composite(df, weights) names of weight vector = original indicator names (no _std)
merge_datasets(df_list) each df must have entity, year, source, rank, score
compare_rankings(df, source_ranks) column name(s) of original rank, e.g. "rank"
sensitivity_analysis() / optimize_weights() same _std-equipped df as compute_composite()

Package advantages and course takeaways

Developing rankflex brought together nearly every major topic covered in STA3005, and the process crystallised several important lessons about writing production-quality R code.

1. The pipe operator %>% makes multi-step pipelines readable.
Functions like compute_composite() use dplyr’s %>% internally to chain group_by(), mutate(), and ungroup() into a single, readable expression. Without the pipe, deeply nested function calls become almost impossible to follow or debug. Writing the package made clear why %>% is a first-class citizen in modern R.

2. ggplot2’s grammar of graphics enables expressive, reusable charts.
plot_ranking_static() and plot_ranking_dynamic() are built entirely with ggplot2 layers — geom_col(), geom_text(), coord_flip(), scale_fill_gradient() — composing them like sentences. This declarative approach means adding a new visual element is a one-line change rather than a full rewrite, a stark contrast to base-R graphics.

3. Roxygen2 keeps code and documentation in sync.
Writing @param, @return, and @examples tags directly above each function means documentation never drifts from the implementation. devtools::document() then auto-generates the NAMESPACE and .Rd files, eliminating a whole class of maintenance bugs that arise when docs live in separate files.

4. Separating concerns with internal helpers improves testability.
The file-reading logic lives in the unexported .safe_read_file(), hidden from the user. This allowed load_data() behaviour — metadata attachment, error on a missing file — to be tested independently of encoding-detection complexity, a direct application of the single-responsibility principle.

5. testthat turns assumptions into guarantees.
Before adding tests, a subtle bug lurked undetected: passing the full long-format rankings_sample to compute_composite() silently produced 0 rows because cross-source NA values poisoned the _std columns. A test asserting nrow(result) > 0 caught this immediately and forced a cleaner data-flow design (filter to one source before standardising).

6. Linear programming (lpSolve) turns an open question into a precise answer.
optimize_weights() frames “what weighting scheme makes university X look best?” as an LP problem — maximise a linear objective subject to simplex constraints. This demonstrates that R packages need not be limited to estimation and inference; optimisation belongs here too.

7. gganimate extends the grammar of graphics to time.
plot_ranking_dynamic() adds just three gganimate layers (transition_states(), ease_aes(), enter_fade()) to an otherwise standard ggplot2 object to produce a racing bar chart. Because gganimate is built on top of ggplot2’s layer system, the conceptual leap from static to animated is surprisingly small.

8. Domain-agnostic design requires deliberate abstraction.
Early versions hard-coded university-specific column names everywhere. Refactoring to accept user-supplied entity_patterns, rank_patterns, and source strings — and validating with synthetic non-university data — forced a clean separation between what the function does and what the data means, which is the essence of reusable software.

9. dplyr verbs express grouped operations more safely than base R.
compute_composite() assigns composite ranks within each year using group_by(year) %>% mutate(composite_rank = min_rank(-composite_score)). The equivalent base-R approach with ave() or tapply() is more verbose and easier to get wrong when groups contain ties. dplyr’s verb-based API makes intent explicit and handles edge cases consistently.

10. LazyData: true and usethis::use_data() make bundled datasets frictionless.
Packaging the cleaned rankings_sample dataset with usethis::use_data(..., compress = "xz") and declaring LazyData: true in DESCRIPTION gives users instant data(rankings_sample) access with zero loading overhead until the object is actually referenced — a small ergonomic detail that makes vignettes and examples dramatically easier to write and run.
